# Лабораторная работа №7 — Программирование

Многопоточное клиент-серверное приложение для управления коллекцией объектов `HumanBeing` с хранением в PostgreSQL, регистрацией пользователей и разграничением прав доступа. Продолжение [лабораторной работы №6](https://github.com/AlexPer777/lab6_ext).

**Курс:** 2-й семестр, весна.  
**Протокол:** TCP (Transmission Control Protocol).  
**Вариант:** 90384.

## Возможности

- Хранение пользователей и объектов коллекции в PostgreSQL.
- Генерация идентификаторов объектов с помощью последовательности базы данных.
- Загрузка коллекции в память при старте сервера.
- Выполнение команд чтения над коллекцией в памяти.
- Изменение коллекции в памяти после успешной записи в базу данных.
- Регистрация и проверка логина и пароля с каждым запросом.
- Хранение хешей паролей, вычисленных алгоритмом SHA-256.
- Просмотр всех объектов и изменение только собственных.
- Многопоточное чтение, обработка запросов и отправка ответов.
- Сериализованные запросы и ответы, неблокирующий сетевой клиент и логирование через Log4j 2.

## Требования задания

1. Перенести хранение коллекции из файла в PostgreSQL и генерировать `id` средствами БД (`sequence`).
2. Обновлять коллекцию в памяти только после успешного изменения БД; команды получения данных должны читать коллекцию в памяти.
3. Реализовать регистрацию и авторизацию, хранить пароли в виде SHA-256-хешей.
4. Запретить выполнение команд неавторизованным пользователям, сохранять владельца каждого объекта.
5. Разрешить просмотр всех объектов, а изменение — только принадлежащих пользователю.
6. Передавать логин и пароль с каждым запросом.
7. Читать запросы и отправлять ответы через `ForkJoinPool`, обрабатывать каждый запрос в новом `Thread`.
8. Синхронизировать коллекцию средствами `Collections.synchronizedXXX`.

### Обработка запросов

| Этап | Реализация |
| --- | --- |
| Чтение запроса | Отдельный `ForkJoinPool` |
| Выполнение команды | Новый `java.lang.Thread` |
| Отправка ответа | Отдельный `ForkJoinPool` |
| Хранение объектов в памяти | `Collections.synchronizedList` |
| Индекс объектов по идентификатору | `Collections.synchronizedMap` |

В базе хранятся таблицы `users` и `human_beings`; поле `owner_id` связывает объект с владельцем. Идентификаторы объектов — числовые, получаемые из `human_being_id_seq`. Оставшийся в репозитории `collection.json` не используется сервером для хранения коллекции.

## Команды

| Команда | Действие |
| --- | --- |
| `register login password` | Зарегистрировать пользователя |
| `help` | Справка |
| `info` | Информация о коллекции |
| `show` | Просмотр всех объектов |
| `add {element}` | Добавить собственный объект |
| `update id {element}` | Изменить собственный объект |
| `remove_by_id id` | Удалить собственный объект |
| `remove_at index` | Удалить объект по индексу с проверкой владельца |
| `clear` | Удалить собственные объекты |
| `remove_greater {element}` | Удалить собственные объекты, превышающие заданный |
| `sort` | Отсортировать коллекцию в естественном порядке |
| `count_greater_than_car car` | Посчитать элементы с автомобилем, превышающим заданный |
| `filter_contains_name name` | Фильтрация по подстроке имени |
| `filter_starts_with_name name` | Фильтрация по началу имени |
| `execute_script file_name` | Выполнить доступный серверу скрипт с правами пользователя |
| `exit` | Завершить клиент |

Для ввода объекта выполните `add`, `remove_greater` или `update id` и следуйте приглашениям. Индексы начинаются с 0. Команда `save` не требуется: изменения сохраняются в базе данных при выполнении команд.

## Настройка PostgreSQL

Сервер читает настройки из свойств JVM либо переменных окружения. Свойства JVM имеют приоритет.

| Переменная окружения | Свойство JVM | Значение по умолчанию |
| --- | --- | --- |
| `DB_URL` | `db.url` | `jdbc:postgresql://pg:5432/studs` |
| `DB_USER` | `db.user` | `s501851` |
| `DB_PASSWORD` | `db.password` | Нет, пароль обязателен |

На Helios хост PostgreSQL — `pg`, база — `studs`; имя пользователя и пароль соответствуют учётной записи кафедрального сервера.

Для локального PostgreSQL сначала создайте базу и пользователя, затем задайте настройки в терминале сервера:

```bash
export DB_URL='jdbc:postgresql://localhost:5432/lab7'
export DB_USER='lab7_user'
export DB_PASSWORD='<пароль_пользователя_БД>'
```

Замените значения своими. При запуске сервер создаёт необходимые таблицы и последовательность, если они отсутствуют. Пользователю БД нужны права на соответствующие операции в выбранной схеме.

## Запуск и использование

Из каталога `lab` запустите сервер:

```bash
java -jar lab-server/target/lab-server-1.0-SNAPSHOT-jar-with-dependencies.jar 9876
```

В другом терминале, также из каталога `lab`, запустите клиент:

```bash
java -jar lab-client/target/lab-client-1.0-SNAPSHOT-jar-with-dependencies.jar 127.0.0.1 9876
```

Сервер принимает необязательный аргумент `[port]`, клиент — `[host] [port]`. По умолчанию используются порт `9876` и адрес клиента `127.0.0.1`. В отличие от ЛР №6, серверу не передаётся имя JSON-файла.

1. Введите логин и пароль по приглашениям клиента.
2. Для нового пользователя выполните `register login password`, указав те же данные, которые ввели при старте.
3. Выполните `help`, `show` или `add`.
4. Для смены учётной записи перезапустите клиент: введённые при старте данные прикладываются к каждому запросу.

Учётная запись приложения отличается от пользователя PostgreSQL. Сервер проверяет её при каждом запросе; отдельной команды `login` в текущем клиенте нет. Регистрация доступна до авторизации.

При `execute_script` путь относится к файловой системе и рабочему каталогу сервера. Для открытия проекта в IntelliJ IDEA используйте `lab/pom.xml` и JDK 21.
